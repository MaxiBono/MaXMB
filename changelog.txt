2.0.0:


------------------------------------------------------------------------
1. Trophy Collection (new)
------------------------------------------------------------------------

New: PlayStation Network > Trophy Collection, the trophy pop-up and the trophy level counted
from the trophies earned. trophies.rs (new) reads them; trophies.js / trophies.css (new) show
them. How the stores are read follows SuccessStory (Lacro59, MIT), including its Steam emulator
reading (from its history: removed in 3.7.1).

- Only the games in the system have trophies (content\Games, by hand or from Game Recognition).
  Each game's source is found once and kept per user (cache\trophies\sources\<user>.json, with
  the game's stamp: found again when the game changes), from where the game came from:
  - PS3 games: RPCS3's own trophy folder (dev_hdd0\home\<user>\trophy\<NP communication ID>:
    TROPCONF.SFM, TROPUSR.DAT, TROPxxx.PNG), found through the game's TROPDIR (np_comm_id), or
    by the game's name (rpcs3_by_name, likeness 0.85 or more). Their own grades and Platinum.
    - The RPCS3 roots looked in (rpcs3_roots): the game's own install, a dev_hdd0 kept
      elsewhere (vfs.yml), every RPCS3 Game Recognition knows (game_sources.json), and first
      the RPCS3 the game's own shortcut starts (a disc image or a game outside RPCS3 is played
      in the one its shortcut names: Minecraft with another install's RPCS3).
    - Not played yet: the game's own list, unpacked once from its TROPHY.TRP into
      cache\trophies\trp\<NP ID> (trp_near, trp_files, trp_dir), nothing won; looked at again
      every 6 s while it runs, until RPCS3 makes its own folder (its trophies won meanwhile pop up).
    - trp_files: the entries read after the TRP's 0x40-byte header (as RPCS3 reads it; 0x60
      tried too), so TROPCONF.SFM, usually the first entry, is found.
    - Disc images (.iso): their copied files (ps3::iso_content) give the NP ID and the list.
    - A game with no list of its own (an unofficial version, a recompilation): the official
      game's, by its name, in RPCS3 or on Steam.
  - Steam games: the achievement list (names, descriptions, hidden, pictures, players' share)
    from Steam's public list (IPlayerService/GetGameAchievements, no account; kept a week in
    cache\trophies\schemas, used however old offline), else Steam's own UserGameStatsSchema,
    else an emulator's own steam_settings\achievements.json. Which are won:
    - Steam's own files (appcache\stats\UserGameStats_<account>_<appid>.bin, binary KeyValues),
      for the Steam ID of Linked Accounts or the account signed in to Steam (loginusers.vdf).
    - The Steam emulators' files (emu_files / parse_emu): Goldberg / GSE (AppData, or the game's
      own folder through steam_settings\local_save.txt), CODEX, RUNE, EMPRESS, OnlineFix,
      SKIDROW, CreamAPI, SmartSteamEmu (stats.bin, names by CRC32), ALI213, Hoodlum,
      DARKSiDERS, RLD! / 3DM, TENOKE (SteamData\user_stats.ini / achievements.toml, TOML lines,
      or %APPDATA%\TENOKE\<appid>), GreenLuma (the registry). INI / JSON / TOML / binary forms,
      hex and shortened times.
    - The app ID: Game Recognition's, the game's store link, steam_appid.txt, an emulator's
      .ini (steam_emu.ini, steam_api.ini, cream_api.ini, ColdClientLoader.ini, SmartSteamEmu.ini,
      ALI213.ini, valve.ini, SteamConfig.ini, hlm.ini, ds.ini, OnlineFix.ini's RealAppId,
      tenoke.ini's "id", in a Unity game's <name>_Data\Plugins\x86_64 too), or Steam's store by
      the game's name (steam_by_name: kept in schemas\names.json, a miss asked again after a
      week, one search every 1.2 s, a store not answering left alone for a minute).
    - With a Steam Web API key: the account's own (ISteamUserStats/GetPlayerAchievements), only
      for a game with nothing on this computer.
  - Epic Games: the game's list (GraphQL productAchievementsRecordBySandbox, kept 30 minutes)
    and the account's won ones, signed in; the namespace from the game's .mancpn / .egstore, or
    the account's game of its name.
  - GOG: gameplay.gog.com's achievements of the game's client ID (goggame-<id>.info / .id, or
    the build's manifest), signed in; without signing in, a public profile's (by its username).
  - RetroAchievements: the game played on the account with the game's name.
- Grades for stores without them (grade_for): under 8 % of players Gold, under 17 % Silver,
  else Bronze. A Platinum added to every game but PS3 games ("<Game> Platinum Trophy", won on
  the day of the last other one); add-on (DLC) trophies marked, listed last, not needed for it.
- The trophy record (cache\trophies\earned): what's been seen won stays won (a file deleted or
  damaged, an emulator's file gone, another emulator's later time), and an account's trophies
  are forgotten with the account.
- The sync (trophies_sync_needed / trophies_refresh): the sync screen ("Performing the sync
  operation for trophy information... Please wait.", its progress, Circle Cancel) when
  something changed since the last one or the stores are due (every 10 minutes); each game read
  again only when its files, accounts or source changed (sig_for), a game with nothing new
  straight in; without any game's trophies, Trophy Collection isn't entered (error sound).
- Account Games (Account Management > Account Games): the accounts' games that aren't in the
  system, listed as "acct:<store>:<id>", each On / Off; their art from the stores.
- Trophies Off in Game Settings: the game out of Trophy Collection and the level at once; a
  game whose won trophies were seen on this computer asks first (they're deleted with it). A
  game known only by its name, renamed: told first that its trophies may change, and looked up
  again under the new name (lib.rs game_renamed; without the internet: renamed_pending.json).
- Lists: games alphabetically (copies numbered), the game's console mark, its progress (the
  share of its trophies won by number, the Platinum included, rounded down) with the bar and the
  Platinum mark once won; a trophy's grade glyph, the locked picture with the padlock (one
  picture the trophy's size, tex_lock_tile.svg, so it never moves apart from it), hidden ones
  as the console's; Triangle menus; a trophy's / a game's Information screens; the user's
  mini card at the top right; long names scrolling before the percentage.
- The trophy level (PS3 table, 1-100: Bronze 15, Silver 30, Gold 90, Platinum 180 points) on
  the user's card and profile, from every game with trophies.
- Cache Management: Delete Trophy Cache (the lists, pictures and what the stores said;
  never the trophies won).
- Game banners: a game's Trophy Collection banner is a file of its own, trophy.* (png, jpg,
  jpeg, webp) in its folder (gameart.rs KINDS, library.rs, models.rs Game.trophy), chosen in
  Game Settings > Game Information > a game > Game Banner in Trophy Collection (from Photos,
  "The game's banner in Trophy Collection."). A Steam game's is Steam's main capsule
  (capsule_616x353.jpg, gameart.rs STEAM_BANNER) through Steam Game Art Scraping; a game with
  none shows its icon (trophies.js). Always shown whole, never stretched.
- A game's Information screen and the game's info in its trophy list show the game's icon (not
  its banner): a game of an account keeps its store's icon with its list (TrophySet.game_icon,
  acct_icon, kept when the cache is pruned).
- The rows of a game's trophies and of the games are a fixed size while chosen (157 x 157 for a
  trophy, the widest game's size for a game), the picture growing inside: the chosen trophy's
  grade, name, description and date no longer shake as the picture grows. Their rows have no
  slide of their own (trophies.css .item.item-trophy: no bounce past their place, a menu's
  opening slide included); their small nudges with the Triangle menus still slide.

2. Trophy pop-ups and watching the games
------------------------------------------------------------------------

- trophypop.rs (new): "You have earned a trophy." as the console's: a 422 x 102 box 85 from
  the top and 103 from the right on 1080 lines, 535 wide and taller for a long name (shown
  whole, wrapped at its spaces), with the trophy sound; one at a time (5.6 s, then 1 s), the
  Platinum after the trophy that completed it.
  - In the menus the page shows it (tpop.js, new, shared); during a game a window of its own
    (popup.html / popup.js, new): always on top, never takes the focus or clicks
    (WS_EX_NOACTIVATE | TRANSPARENT | TOOLWINDOW | TOPMOST), out of the taskbar, with the
    menus' Font, Text Size, Text Color and PS3 theme notification picture (trophy_pop_style).
  - The window is made (hidden) as a game starts (prepare; how long it took, in the log), and a
    pop-up waits until its page says it listens ("trophy-pop-ready", at most 15 s); what it
    showed is logged ("trophy-pop-shown"), and so is each trophy won, where its pop-up went
    (over the game or in the menus), a window that couldn't be made, and the pop-up page's own
    errors ("trophy-pop-note"). Its sound is loaded with the page, and a trophy picture that
    can't be read shows its grade's picture instead.
  - A trophy shared by several copies of a game (the same set key) pops up once (first_time,
    1 minute).
- The watch (start_watch): the game running's files every 1.5 s (others every 10 s): RPCS3's
  TROPUSR.DAT, Steam's own and the emulators' files; its store while it runs (web_every):
  Steam with the key every 4 s (without it 20 s), GOG and Epic every 6 s, a refusal doubling
  the wait (web_wait, at most 160 s). A Steam game with its trophies in files here (Steam's
  own, an emulator's) never asks Steam. RetroAchievements: its own watch (start_ra_watch,
  its recent achievements every second, 5 s after a refusal).
- After a game ends, its store is asked again at 8, 30, 90 and 240 s (AFTER_GAME), and a sync
  within 10 minutes of it pops up what it won at the end (LAST_PLAYED).
- The log notes how long after the store recorded each trophy it was seen.
- The menus' notifications use the pop-up's look too.

3. Linked Accounts and Account Management
------------------------------------------------------------------------

- accounts.rs (new): each user's store accounts, kept in content\data\accounts.dat encrypted
  with Windows' DPAPI (only this Windows user on this computer reads it, with a fixed extra
  secret). The menus only ever see names and IDs, never keys or tokens (accounts_view).
  - Steam: the user's own Steam Web API key and Steam ID (a profile address taken too); a
    private profile is told (Ok("private")). With a key alone, the account signed in to Steam
    on this computer.
  - RetroAchievements: username and Web API key.
  - Epic Games and GOG: their launchers' own sign-in page in a window (web_window, its own
    browser data in content\data\webview_login), as Playnite / SuccessStory do: the system
    never sees the password. Epic keeps the account's ID, name and a renewal token (the
    sign-in's own session closed right after); GOG a renewal token. The Epic
    Account ID option is gone (sign-in only).
  - Sign Out deletes the store's cookies too; Remove All Accounts Information forgets
    everything (keys, IDs, sign-ins, Connect with Steam Friends, the sign-in windows' data,
    the kept Steam picture and saved trophy lists); a deleted user's accounts go with them.
- net.rs (new): every web request through Windows' curl.exe with the address, headers and body
  handed over its standard input (-K -), never on its command line (keys and tokens); https
  only; Steam's community pages left alone after a 429; online() checked at most every 30 s.
- Account Management (steamfriends.js, new): Connect with Steam Friends, Linked Accounts (each
  store's section, its value or "Not Set"), Account Games.
- secret.rs (new): what else is secret is sealed with DPAPI too, written as "dpapi:" and the
  sealed bytes in hex: the game databases' API keys (settings.json), the PlayStation Network
  sign-ins' IDs and passwords (psn.json) and each user's saved Sign-In (users.json). Values an
  older version wrote plain are read, and sealed at the first start (lib.rs secret_migrate) or
  the next save; a sealed value that can't be opened (the file copied to another Windows user
  or computer) reads as empty. Sealing that fails keeps the value out of the file rather than
  writing it plain.

4. Steam Friends (new)
------------------------------------------------------------------------

- steamfriends.rs (new): Connect with Steam Friends (On / Off at any time) shows the Steam
  account's friends in the Friends column, and the user's own card the Steam account (name,
  picture, profile description as the comment, the game being played).
  - With the key: ISteamUser/GetFriendList and GetPlayerSummaries; descriptions from each
    public profile's page. With the Steam ID alone (public profile and friends list): the
    profile's public pages, a friend at a time, the status brought up to date in turns
    (keyless_players).
  - Statuses as the PSN card's: Online (1, 5, 6), Away (2, 3, 4), Signed Out (0) with "Last
    Sign-In: ... Ago"; online first, then away, then signed out.
  - Card colours: a private profile's as Steam shows it; else the main colour of their
    profile background (GetProfileItemsEquipped); else one of the card colours by their ID.
  - Their trophy levels counted from their public Steam games (steam_friend_levels, near the
    cursor first, kept: steam_friend_levels_kept); "–" when their games are private.
  - Kept like every cache (Temp, or the system's folder with Save Cache in System
    Directory): pictures, descriptions, colours, levels, fetched again only when changed;
    without the internet, the friends as last seen. Cache Management: Delete Steam Cache.
- The signed-in Steam account's picture can be chosen as an avatar ("steam").
- Trophy Level (Friends Personalization): Automatic (from the trophies earned, the default,
  given to every user once in 2.0.0), Random (a weighted level: 1-5 60 %, 6-10 25 %,
  11-15 10 %, 16-20 4 %, 21-30 1 %) or Custom; always Automatic with Steam Friends on.
- Statuses checked every minute (was 30 s), on a clock that only runs while the XMB is what's
  shown (not in the Internet Browser, the media players and viewers, the Photo Gallery): it
  goes on from where it was once they close, rather than checking at once.
- A friend whose profile goes public or private is seen at the status checks (list.json, and
  their public page with the Steam ID alone): only that friend's level is counted again, or
  "-" at once with nothing asked of Steam (steamfriends.rs privacy_changed).
- A friend with a public profile whose games or achievements were found private is asked
  again an hour after (trophies.rs PRIVATE_RECHECK, was a day; steamfriends.rs LEVEL_RECOUNT /
  level_due, steamfriends.js _sfLevelsAsk at the status checks too): only those friends, one
  request each. A level counted stands for the session, and a private profile is never asked
  about.

6. PS3 games: disc images, RPCS3's folders and its own RPCS3
------------------------------------------------------------------------

- iso.rs (new): a PS3 disc image read straight from its ISO 9660 file system (no mounting),
  only the small files: PS3_GAME's PARAM.SFO, pictures, preview, music, TROPDIR, and
  PS3_DISC.SFB (its Title ID). ps3.rs iso_game: copied once into
  content\data\cache\ps3iso\<the image's path, size and date>\PS3_GAME; a dumped disc whose
  PARAM.SFO can't be read: the image's name and PS3_DISC.SFB's Title ID. Found in an RPCS3's
  folder, in its games.yml (started by Title ID), or in a source folder (started by the image).
- ps3.rs vfs_dir / hdd_dir / moved_dirs: an RPCS3's dev_hdd0 or games folder kept elsewhere
  (config\vfs.yml, vfs.yml in older versions, $(EmulatorDir)): its games found with it,
  started by it, its trophies read there; the same folder shared by two installs: each game
  once; a drive that isn't there: as if not set.
- gamesrc.rs: a game inside an RPCS3 install is started by that install's RPCS3 (its
  trophies, saves and settings are there); the others by the last RPCS3 found. A shortcut
  that started another RPCS3 than the one the game is in is made again for its own
  (update_ps3_launch). A game found twice (its RPCS3 a source and the folder it's in too):
  once; paths compared however they're written (path_key: "G:\x" and "G:/x").

7. Game Recognition and game art
------------------------------------------------------------------------

- gameart.rs steam_standin: a game recognized as a Steam game (store, app ID, emulator files,
  name), never a PS3 game, gets Steam's own pictures: its logo as the icon (its see-through
  border cut, trim_transparent) and the library hero as the background (an older game
  without one: its store header, zoomed as the hero is). The newer games' addresses with their
  own code come from Steam's store (IStoreBrowseService/GetItems). Never in place of art you
  chose or a PS3 game's own (src_rank: local < databases < Steam < PS3 < yours); once per game
  (steam_art5.json): a picture removed afterwards isn't put back.
  - Steam's pictures only come with Steam Game Art Scraping (below).
- A game renamed by hand: looked up again under its new name (scrape_renamed): what the
  databases find replaces only what they or the program's icon gave it; your art and a PS3
  game's own stay.
  - Its folder in content\Games takes the name typed (lib.rs game_folder_rename,
    gamesrc.rs rename_game_folder: characters Windows doesn't allow left out, numbered when
    the name is taken), and everything that knew the old folder follows it: the recognized
    games' list, steam_art5.json, renamed_pending.json, its trophy source and list
    (trophies.rs folder_renamed), what was played last and Game Settings' open menus.
- Game Recognition only finds games (lib.rs game_sources_sync, scan_library): their art comes
  from two options of their own in Game Settings, each running over every game in the Games
  folder with the loading icon and a count, and told when done ("Art found for N games" /
  "No new art found", or why not: no internet, no database set up):
  - Steam Game Art Scraping (lib.rs game_art_steam): Steam's pictures for every game recognized
    as a Steam game that has no icon, background or Trophy Collection banner, or whose icon or
    background is its program's own or the databases' (steam_art_wanted); Steam's take the
    place of the databases' art, never the other way around.
  - Game Settings > Game Art Databases (moved out of Game Recognition, was Game Databases;
    "Enter the keys to access the game art in SteamGridDB, TheGamesDB or RAWG."): Game Art
    Database Scraping (lib.rs game_art_db, in place of Automatic Scraping) gets the art of
    every game with no icon (or only its program's own) or no background; a game with an icon
    of its own and a background is skipped (needs_db_art). For the games it doesn't skip: a
    video when there's none, the name and the console too.
  - Both look again for what a game is missing, one removed before too (gameart.rs
    FILL_MISSING), never a PS3 game or PlayStation Home, never in place of what you chose; a
    game unchanged since it was last asked about isn't asked again (game_lookups.json; the
    databases' setup mark keeps its first character, so the games looked up before stay so).
- A game's pictures changed on disk show at once (models.rs Game art_stamp: the files' dates;
  a new date, a new address, so no copy kept from before is shown).
- gamesrc.rs: a source folder added again brings back its games whose folders are gone
  (source_added); one change to the list of recognized games at a time (SYNC), so a folder
  removed during a search can't leave its games listed; the listed folder itself is never
  taken for a copy of itself (repair).
- Program icons: a blank one (all black, as Windows gives for some Unity games at 256 px) is
  made from the largest smaller size that has colours; blank icon.png files from before are
  made again (drop_blank_icon). A game started through its store's link takes its own
  program's icon.
- Program icons are centred in their picture (gamesrc.rs center_png / center_local_icon, once
  per session; the shading cache's key changed so they're made again).

8. Menus and scrolling
------------------------------------------------------------------------

- xmb.js _smoothList: the media lists (Music, Photo, Video, Game, Friends, your own sections,
  Trophy Collection) and every other list scroll as the console's, measured on its capture
  frame by frame: a held direction repeats 300 ms after the press, then a row every 66.7 ms
  (main.js holdPace, on its own clock); each row closes 0.6 of its distance every 1/30 s
  (e^(-t / 65.2 ms)), so the list follows the button about a row behind, never jumping;
  more rows a repeat when held long. Pressed: a row's details at once; held: its background,
  preview and music once the list stops.
- marquee.js: long names scroll as the console's: still 2 s, then left at 89 px a second (on
  1080 lines) until gone, half a second gone, back at the start with a short fade. A name
  written anew always scrolls again (it could stay stuck at its start).
- Menu Blur (Power Save Settings): Original, All (the Web browser too), Off (the older "Remove
  Menu Blur: On"). Every blurred background is blurred the same, 6 px; the background blurred
  in Trophy Collection, Settings' menus and Account Management.
- Settings' options: their wrench icon at the console's size, growing from it when entered.
- The loading icons turn together, and one drawn again goes on from where it was.
- Text shadows of the date, time and friends' count, and the clock's face, fitted to the
  reference pixel by pixel.
- Logging in: the box grows, then its profile slots fade in.
- The mouse pointer only shows for a mouse that really moved (not when what's under a still
  pointer changes, nor going in or out of full screen).
- Every list (xmb.js _smoothXY, _smoothTick) settles without shaking: its rows move in whole
  pixels of the screen (Windows' display scaling counted: 1.25 page pixels at 125 %), so a
  row's name and details and its picture no longer go a pixel each their own way, up and down,
  at every step; they stop the moment what's left rounds to none, and the rows' usual slides
  come back a frame after the last one is in place (given back in the same frame, the last
  pixel crept into place again, a fraction at a time). A row placed again up or down slides
  there without going past its place and back (styles.css .item: no vertical bounce; sideways,
  into and out of a menu, it still does). Each row's place is itself on a whole pixel of the
  screen (xmb.js _layoutItems), and its box no longer grows with its picture as it's chosen
  (styles.css .item: a box of no size at its place, its picture and name centred on it, as the
  Trophy Collection's rows already were): its name and details, placed again from the box's
  middle at every step of the growing, landed on a pixel or the next and shook up and down in
  Settings, Music, Game and every other list.
- Text: every text smoothed alike, in shades of grey (WebView2 --disable-lcd-text): text on
  something solid (a friend's comment in its bubble, some names) was drawn with Windows'
  coloured ClearType edges, jagged beside the rest.
- Text and Color: Clock Shadow and Date and Time Shadows (On by default, no descriptions),
  after Clock Color: off, the clock (its face's shading too) or the date, time and friends'
  count are drawn without their shadows, the light one every text has included
  (user.theme.clockShadow / infoShadow; saved in presets and Custom Themes).
- Menu Blur Off: the menus' backgrounds take the same shade as with it On (the profile's big
  card was much darker).
- Photo Gallery: a picture still loading shows the loading icon (not a missing picture); the
  Flat Icon Style's loading icons take the Icon Color (--icon-flat).
- What's New: its icon when chosen at the size of the console's.

10. Media
------------------------------------------------------------------------

- video.rs: H.264 the webview can't show (High 10, High 4:2:2, High 4:4:4, 10 / 12-bit; common
  in MKVs) is converted, not only repacked (VideoInfo.hard_pic, read from the avcC /
  CodecPrivate by vprobe.rs and from FFmpeg's report); the video itself is copied, never a
  cover picture kept with it (-map 0:V:0?); why a copy failed and how long it took, in the log.
- Video icons: a new file name each time ("<key>_<when>"), so the old picture isn't shown
  again from the webview's cache; the older ones deleted.
- cachesweep.rs (new): the decoded songs and converted videos are noted next to them
  (decoded.tsv / videos.tsv); at every start the copies of files changed or gone since are
  deleted (they only ever grew).
- medialib.rs forget_missing: files read before that aren't there any more are forgotten at
  start (a drive unplugged: kept).
- docs.js: what's kept stays limited over a long session: the 3 documents opened last stay
  open, each keeping its last 16 pages; the last 400 small first-page pictures.
- glasslayer.js / iconshade.js: the glass and glow shapes made for a theme's icons are
  dropped with the theme (changing themes all day kept adding to the graphics memory).
- video.rs: a copy's sound is always in one of AAC's standard layouts (mono, stereo or 5.1:
  aformat=channel_layouts=mono|stereo|5.1): an MKV's 5.1 (side) sound (E-AC-3 / Atmos films)
  and 7.1 were written with a layout of their own, which Windows' AAC decoder refuses, so the
  copy didn't play ("PIPELINE_ERROR_DECODE").
- A playable copy the player can't play is deleted (lib.rs video_drop_copy), so it's never
  played again in place of a good one: a copy saved from before is made again; one just made
  shows the error. Why the webview refused it goes in MaXMB.log (videoplayer.js _onError).

11. Fixes
------------------------------------------------------------------------

- hidpad.rs: HIDP_CAPS was 44 bytes where Windows writes 64: HidP_GetCaps wrote 20 bytes past
  it each time a PlayStation controller was opened (often while RPCS3 used it), which could
  crash the system (STATUS_HEAP_CORRUPTION). Its size, HIDD_ATTRIBUTES' and
  SP_DEVICE_INTERFACE_DATA's are now checked when it's built.
- Glow and Glow (Pulse): the PlayStation Network logo (a full-colour picture with a dark border)
  and YouTube's picture glow too, the glow's colour lifted to be seen (xmb-iconstyle.js
  glowLift).
- Game column by folder: a game deleted inside a folder goes at once, the folder's last one

1. Original Wave Style (the PS3's own wave)
------------------------------------------------------------------------

New: src/js/ps3wave/ - a JavaScript/WebGL2 port of sagemono/moyou (MIT, (c) 2026 sagemono),
drawing the XMB wave from the console's own lines.qrc (firmware 4.93).

- formats.js: QRC container reader (QRCC deflate + QRCF tree), .mnu parameter files, DDS and
  TGA textures.
- rsx.js: RSX Cg binary (.vpo / .fpo) to GLSL ES 3.00 translator (container parsing,
  microcode decoding, GLSL emission), output identical to moyou-cli transpile with hwprec.
- params.js: the console's parameter schedule (month maps, time-of-day presets, fades), with
  MaXMB additions: per-key mods (Wave and Sparkles Personalization scales the console's
  values), screen-preset overlays (override/music_1 for the Music Player's Visualizer Wave)
  faded by the clock, and a month override for PS3 themes.
- sim.js: the rope / wave simulation (sim/wave.cpp), warmed from a straight rope
  (36000 + 3000 n steps) to the console's start state.
- particles.js: the sparkles, with round-toward-zero float arithmetic as on the console.
- renderer.js: the full frame - background (back_colours0-2), wave sheet (lines1),
  LinesController, the HDR glare chain (GlareSourcePre, Copy, mips, Gaussian, AccGlare),
  ToneApplyDisplay and particles. MaXMB additions: a custom background map for Background
  Color squares, the wave without its background (over a picture or video), wave and sparkle
  colors, and the background rendered on its own (for icon / menu colors).
- original.js: the Wave Style driver (same controls as linkev's wave in wave.js): Background
  Color, Month and Time Colors, colors, waves / sparkles on or off, wallpaper, Still Waves,
  FPS Cap, focus and in-game power saving, controller motion.
  - Graphics safety: shaders compiled in the background with a start deadline; falls back to
    linkev's wave on context loss, start timeout or under 10 fps (remembered per computer).
  - Drawn at most at 1080 lines (540 minimum) and stretched to the window; follows
    Display Settings > Resolution.
  - Idle when nothing of it shows (waves and sparkles off over a picture / theme background,
    or the screen covered: body classes mpfull, pv-open, video-open); woken at once by _kick.
  - Background color read back asynchronously (backgroundPixelsStart/Take) and cached; the
    cache key includes the screen-preset overlay state, so colors aren't reused after the
    Music Player's Visualizer Wave fades out.
- warm.worker.js: the rope warm-up runs in a Web Worker while the shaders compile.
- wavecache.js (new): Wave Cache - the warmed rope state (Float64, cur + vel, base64) saved per
  settings key (up to 8, most recently used kept), bit-identical to a fresh run.
- background.js: the console's month / time-of-day background on its own (64 x 36), used for
  linkev's wave with Month and Time Colors and for icon colors; pre-built 8 s after start and
  kept across Wave Style changes.
- monthbg.js (new): MaXMB's own measured model of that background (PCA, 20 components) for when
  lines.qrc isn't there, so linkev's wave still shows the console's month colors.
- custom_render_plugin.prx is no longer needed (rope start states are computed, not read from
  the .prx); only lines.qrc is.
- wave.js: drives either style (Original / linkev); icon auto color, menu tint and glow taken
  from the live background; colors refreshed after a screen-preset fade (600 ms, 1.5 s).
- Background Color squares refitted row by row to console captures for the Original style
  (ORIG_SQUARES).
- intro.js: the boot intro starts on black and the background / wave rise to the menu's color
  and stay there (both styles).
- "linkev's" renamed "linkev" everywhere in the UI.

2. Music Player: Visual Player (Canyon and Earth)
------------------------------------------------------------------------

New: the PS3's Music Player visualizers, reverse-engineered from soundvisualizer_plugin,
custom_render_plugin, qgl_canyon_app, qgl_gaia_app and qglbase (firmware 4.93, Ghidra).

- spectrum.js: the console's spectrum - 512 stereo samples at 48 kHz, Gaussian window, FFT
  scaled 1/512, 17-tap Gaussian smoothing, 256 log-spaced bands, 3*ln(512m+1)/ln(513).
  SpectrumTap reads the Music Player's <audio> through a 48 kHz Web Audio graph (two
  analysers) and undoes the element's volume, so the visualizer reacts the same at any volume
  (the console reads the music before its volume).
- canyon.js: Canyon on WebGL2 from canyon.qrc - presets and settings (.mnu), normal map, RSX
  programs via rsx.js; terrain commit physics as decompiled (valley shape, damped spring per
  column, 5 smoothing passes, normals), 128 x 128 quad ring, color LUT, fog, line effect;
  depth of field (canyon_blur_ammount, 5 x canyon_layer_blur_blur, 256 x 144 x 4 blur
  pyramid) and feedback (canyon_layer_blur.fpo). Preset groups and timings as in
  custom_render (Bir, Voyage, Volcano, Volvic, Blue), terrain reset and 2 s morph on a new song.
  - Blur pyramid steps set to [0.5, 1, 2, 4] texels (slice 0 averaged, not blurred), matched
    to the console's video capture.
- earth.js: Earth from earth.qrc - cube faces from 2 x 2 JPEG tiles per face (layout worked
  out from the tile seams), stars and sun disk, the 30 camera flights (qglbase camera path:
  cubic segments, time-weighted key slopes), sun direction, per-flight settings; atmosphere
  drawn per pixel with Sean O'Neil's scattering model (GPU Gems 2) using the console's
  wavelengths and sun intensity; tuning (EARTH_TUNE) matched to a console video capture.
  - Faces prepared with canvas transforms (no per-pixel loops, no getImageData read-back),
    uploaded straight from an OffscreenCanvas, one face per task; verified pixel-identical
    to the previous method on all 18 faces.
- Both visualizers draw at about 60 fps (12.5 ms minimum between frames) whatever the display
  refresh rate or V-Sync setting.
- ui.js (MusicPlayer):
  - Square cycles Visualizer Wave -> Canyon -> Earth -> Visualizer Wave; a missing .qrc is
    skipped with a note naming the file.
  - Visualizers Cache: Canyon and Earth created 1.5 s after the player opens and drawn once
    while hidden (prepare()), shared through promises (_canyonReady / _earthReady), so
    switching is immediate. Freed on close (WebGL contexts lost, canvases removed, archives
    dropped) unless Save Cache in System Directory is on.
  - The <audio> element is CORS-enabled from the start and routed through the Web Audio graph
    when the player opens, so the song is never reloaded when a visualizer starts.
  - The Web Audio context is suspended when the player closes and resumed when it opens.
  - Visualizer canvases use visibility (not display) so they keep their size while hidden.
- ps3.rs / lib.rs: the PS3's own files (lines.qrc, canyon.qrc, earth.qrc) read from
  resources/ps3 only (command ps3_file, KNOWN list); in debug builds also from
  src-tauri/resources/ps3 and src-tauri/ps3. src-tauri/resources/ps3/README.txt added;
  the folder's contents are git-ignored.

4. Games and launching
------------------------------------------------------------------------

- gamesrc.rs:
  - Store launchers: Steam (app manifests .acf, steam://rungameid), Epic Games, GOG (game
    info play tasks), Amazon Games and Battle.net games started through their launcher;
    EA app / Ubisoft Connect from their own program. Games found earlier are upgraded on the
    next scan unless edited by hand (upgrade_store).
  - Steam folders: the Steam root, a library, steamapps or steamapps\common can be added;
    Steam's own .url shortcuts start through Steam with Steam's icon.
  - Source folder modes: By Folders / By Executables ("How the Games are separated"), stored
    per folder (sync_modes); new folder rule: a folder is one game when it has a real root
    program (or inner game folders / game files, or root programs plus an uninstaller), and
    a folder of games with a loose installer or tool is still read one game per subfolder.
  - PS3 games: a Windows .lnk written per game (write_lnk / write_ico / rpcs3_cmdline), the way
    RPCS3's Create Shortcut makes them (--no-gui, by Title ID or EBOOT.BIN, with the icon).
  - Names ending in "Game" kept; duplicates across two source folders listed once.
  - Tests added (Steam, launchers, separate apps, edge cases, end-to-end installer case).
- library.rs: loose shortcuts / programs in content/Games wrapped in a folder of their own
  (wrap_loose_shortcuts).
- launcher.rs:
  - LaunchPlan::Raw: an .lnk pointing at RPCS3 starts RPCS3 directly with its exact argument
    line (raw_arg), not through cmd start.
  - Every game / program is spawned with NORMAL_PRIORITY_CLASS (it no longer inherits the
    app's lowered priority).
- focus.rs:
  - Follow: the game is followed by its pid, its descendants, processes running from its
    folder and new foreground programs; programs already running at launch are ignored;
    180 s timeout when the game never shows.
  - In game, the app and its WebView2 processes drop to BELOW_NORMAL, and so do the app's own
    FFmpeg processes (preloads, conversions, stills); restored afterwards.
- focus.rs: game mode ends when the app's own window is in front for two checks in a row
  (after something else was, once the game has been seen), even if a launcher or part of
  the game is still running; the launchers' helper processes (GameOverlayUI, Steam's
  error reporter and service, Epic's web helper, GOG Galaxy's helper, EA's background
  service) are never taken for the game; what's followed, the end, and what was still
  running when the user came back by hand are written to the log.
- focus.rs: a program already running before the game (by its file, e.g. SynTPEnh.exe
  restarting when the screen mode changes) or one in C:\Windows is never taken for the
  game; every way back from a game goes through return_from_game, which also repairs the
  window once per game (un-minimized and shown; the webview hidden, shown and set to the
  window's size, at once and again a second later, so the page draws anew; the window's
  own full screen is left alone) and logs its state; game_mode_end does the same repair.
- xmb.js: the page logs when it shows the menus again after a game.
- lib.rs: WebView2 starts with CalculateNativeWinOcclusion off, so the page never stops
  drawing because Windows reports its window as covered (after a full screen game the
  report could stay stuck: an invisible window and a sleeping page). Losing the focus or
  being minimized still quiets the app.
- focus.rs: "back in the app (the game has ended)" when nothing of the game is left.
- focus.rs: when the game's window opens while the app still has the focus (a game
  started through its store's client), the game's window is given the focus (once per
  window); the app also lets any program take the foreground when a game starts.
- focus.rs / lib.rs: after a game the page must answer (game_mode_end) within 8 seconds;
  if it doesn't (it stopped running during the game), it's loaded again. Both are logged.
- focus.rs: bring_to_front takes the foreground from a thread of its own (the window's
  thread only un-minimizes the window and focuses the page), and force_foreground no
  longer joins the foreground program's input (AttachThreadInput): with a program that
  didn't answer (a closing Steam game) it froze the app's window thread, leaving the
  window black or see-through and the page deaf. The game's window is given the focus
  the first time it's found without it, whoever had it (logged with who had it); the
  page's reload logs whether the window's thread still answers.
- focus.rs / lib.rs: a page that doesn't answer after a game is no longer reloaded (that
  didn't bring it back: WebView2 itself had stopped) but made anew with its window: the
  window is closed (the app kept running meanwhile: RunEvent::ExitRequested is held
  back), what's left of the app's own WebView2 processes ended, and the window built
  again as at the start (build_main_window, shared with the start). The log notes how
  many WebView2 processes the app had when the game started and when the page stopped.
- focus.rs: while a game runs, the log notes when the app's WebView2 processes end (with
  the program in front at that moment), and when the page stopped, whether WebView2
  wrote crash reports (EBWebView\Crashpad\reports in the webview folder) since the game
  started.
- focus.rs: when the page's processes ended during the game, the window is made anew as
  soon as the game ends (no 8-second wait), and their exit codes are logged.
- focus.rs / lib.rs: once the game is running, the page (the webview) is hidden until
  the game ends, so it draws nothing while the game changes the screen's mode; the
  window is black behind it (background_color), and the graphics card is left to the
  game. The log tells the order and timing in which the page's processes ended, and
  which one was the main one.
- focus.rs: when the page's processes end during a game, the log also lists the programs
  started since the game was (not the game's own) and the ones that ended along with them.
- focus.rs: the game watch's decisions (back in the app, the game's window given the
  focus, the game seen, ended or never shown) moved into GameWatch / BackWatch /
  hand_off, apart from Windows, with tests of whole sessions (a Steam game from start to
  end, Alt+Tab back with the game still open, a slow game loading behind the app, a game
  that never shows, a local game starting the real one, a store link). The game's folder
  is matched the same way on every system (tests).
- focus.rs / lib.rs / xmb.js: a program from a custom section (launch_game with
  program: true) no longer has the app's page hidden while it runs.
- focus.rs / lib.rs / main.js: the page answers "game-exited" at once (page_alive), so a
  living page is never taken for a stopped one (a program from a custom section didn't
  answer before, and its window would have been made anew 8 seconds later).
- lib.rs / focus.rs: the window getting the focus during a game (Alt+Tab or a click back)
  shows its hidden page at once, which then ends game mode by itself. The page is hidden
  only once the game has taken the front from the app (hiding it while the app was in
  front, as a game started directly loaded, gave the window the focus, which was taken
  for the user coming back: game mode ended before the game began), and the focus shows
  only a page the watch hid. Test: a local game starting with the app still in front.
- focus.rs / xmb.js: only the game's own window counts: the user is "back in the app"
  only after the game itself was in front, and the page is hidden only once the game's
  window is in front. A launcher's window (Steam's "launching" box) closing hands the
  front back to the app while the game is still loading (on a slower PC for a long
  while), which ended game mode before the game began. The page no longer ends game mode
  on the window's focus alone (the backend shows the hidden page when the user is back,
  which ends it). Tests: a launcher's box closing; a slow PC's Steam game from start to
  end; the page side (headless).
- wave.js: Still Waves and the power level are kept and given to every wave renderer made
  later (another user's Wave Style, or the linkev wave taking over from an Original wave
  that failed); before, the waves moved again with Still Waves On. xmb.js: a new user's
  first sign-in applies the Power Save Settings too.
- xmb.js: programs from custom sections end game mode as soon as the user is back in the app
  (game_mode_end on focus), so the controller works on the first press.
- Game panel (Triangle): consistent icon growth / name shift whether a preview, background or
  hidden title is involved; game music plays even with Background Music off.
